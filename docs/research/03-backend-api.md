## 1. NetworkManager D-Bus

**SecretAgent.** Daemon claims bus name, owns object implementing `org.freedesktop.NetworkManager.SecretAgent` at `/org/freedesktop/NetworkManager/SecretAgent`, and calls `AgentManager.Register(identifier)` (or `RegisterWithCapabilities`, with `VPN_HINTS` cap) on `/org/freedesktop/NetworkManager/AgentManager`. Identifier must be unique reverse-DNS-ish, and the caller needs a user session (NM identifies the agent by uid/session; polkit `org.freedesktop.NetworkManager.settings.modify.own` is relevant) [K]. Methods: `GetSecrets(connection, connection_path, setting_name, hints, flags)`, `CancelGetSecrets`, `SaveSecrets`, `DeleteSecrets`. GetSecrets flags [V]: ALLOW_INTERACTION 0x1, REQUEST_NEW 0x2 (previous secret was wrong: do not return cached), USER_REQUESTED 0x4, WPS_PBC_ACTIVE 0x8; NO_ERRORS/ONLY_SYSTEM are internal. Secret flags per secret (`psk-flags` etc.): 0 system-owned (stored in the profile, readable by NM), 0x1 agent-owned (never stored by NM; agent must supply each time, or store itself e.g. in keyring), 0x2 not-saved (ask every time), 0x4 not-required. Rule: frontend must be able to answer GetSecrets for agent-owned and not-saved secrets, and implement SaveSecrets/DeleteSecrets if it stores them. `Settings.Connection.GetSecrets` only returns persistent secrets or those from an agent in the requester's session and never prompts [V]. Secrets are excluded from GetSettings [V].

**AddAndActivateConnection2(connection, device, specific_object, options)** [K]: returns path, active_connection, result dict; options include `persist` ("disk"/"memory"/"volatile") and `bind-activation`. This is the right call for "connect to new SSID" because a memory-only profile can be created and only saved after success (avoids polluting disk with failed-password profiles).

**Update2 / Save** [V]: flags 0x1 to-disk, 0x2 in-memory, 0x4/0x8 in-memory variants (detached/only), 0x10 volatile, 0x20 block-autoconnect, 0x40 no-reapply. args: `plugin`, `version-id` (nonzero fails if profile version changed: use for optimistic concurrency against nm-connection-editor/nmcli edits). Empty settings keeps current. Unsaved changes are lost on reload [V]. `Device.Reapply(connection, version_id, flags)` applies a subset of changes live without reconnecting [K].

**Checkpoints** [K for semantics, V for flags]: `CheckpointCreate(devices, rollback_timeout, flags)`, `CheckpointDestroy`, `CheckpointRollback`, `CheckpointAdjustRollbackTimeout`. Flags [V]: DESTROY_ALL 1, DELETE_NEW_CONNECTIONS 2, DISCONNECT_NEW_DEVICES 4, ALLOW_OVERLAPPING 8, NO_PRESERVE_EXTERNAL_PORTS 0x10, TRACK_INTERNAL_GLOBAL_DNS 0x20. Yes it is usable as a "dead-man's switch" (like `nmcli` checkpoint): create with timeout (e.g. 30s), apply change, confirm to destroy, otherwise NM auto-rolls back. Caveats: rolls back NM-managed device config and connections, not external state (rfkill, firewall, resolved overrides, VPN server side); needs polkit `org.freedesktop.NetworkManager.checkpoint-rollback`; a rollback re-activates old profiles, which may need secrets again; only one non-overlapping checkpoint per device unless ALLOW_OVERLAPPING. NEWS 1.50-1.58 lists no checkpoint changes [V]. Good for: changing static IP/DNS/route/MTU/proxy on a remote or sole link. Not needed for ordinary Wi-Fi connect.

**Device state / reasons.** `Device.StateChanged(new, old, reason)` and `ActiveConnection.StateChanged(state, reason)` (NMActiveConnectionStateReason: unknown, none, user-disconnected, device-disconnected, service-stopped, ip-config-invalid, connect-timeout, service-start-timeout, service-start-failed, no-secrets, login-failed, connection-removed, dependency-failed, device-realize-failed, device-removed). Device reasons are 0..79 [V]. Suggested mapping for UI text:
- NO_SECRETS(7), SUPPLICANT_DISCONNECT(8), SUPPLICANT_TIMEOUT(11), SUPPLICANT_FAILED(10): treat as "authentication failed / wrong password" when occurring in NEED_AUTH->FAILED or during CONFIG with PSK (see pitfalls: not unambiguous).
- DHCP_START_FAILED 15, DHCP_ERROR 16, DHCP_FAILED 17, IP_CONFIG_UNAVAILABLE 5, IP_CONFIG_EXPIRED 6: "connected to network but no IP address".
- SSID_NOT_FOUND 53: out of range / hidden not found.
- CONFIG_FAILED 4, IP_METHOD_UNSUPPORTED 65, IP_ADDRESS_DUPLICATE 64.
- USER_REQUESTED 39, CONNECTION_REMOVED 38, NEW_ACTIVATION 60, CONNECTION_ASSUMED 41: not errors; do not toast.
- SLEEPING 37 / UNMANAGED_MANAGER_DISABLED 73, NETWORKING_OFF 78, CARRIER 40, REMOVED 36, FIRMWARE_MISSING 35.
- MODEM_*/GSM_*/SIM_* 23-34, 45-48, 52, 57-59, 79; BT_FAILED 44; DEPENDENCY_FAILED 50; SECONDARY_CONNECTION_FAILED 54 (VPN secondary).
- UNMANAGED_* 69-77 explain why a device is unmanaged; 74-77 are config-driven.
Always keep a fallback "Unknown reason (N)" because the enum grows.

**Connectivity / captive portal.** `NetworkManager.Connectivity` (UNKNOWN 0, NONE 1, PORTAL 2, LIMITED 3, FULL 4), `ConnectivityCheckAvailable/Enabled/Uri`, `CheckConnectivity()` forces a probe. PORTAL means HTTP probe got a redirect/unexpected body; frontend opens browser to the portal (NM does not give the portal URL over D-Bus; many clients re-fetch the probe URI or run `xdg-open` on the check URI; the NM dispatcher `90-nm-cloudflared`-style hooks are not needed) [K]. Enabled via NetworkManager.conf `[connectivity]` (uri, interval, response); per-device in 1.58: new option to disable check on selected interfaces, link-local DNS only, internal ping, stale global state fixed [V]. Connectivity is per-device (`Device.Ip4Connectivity`, `Ip6Connectivity`) and global.

**Hotspot / AP.** `Wifi` setting mode=ap, with ipv4.method=shared (NM runs dnsmasq/internal DHCP + NAT) [K]; `Device.Wireless` `WirelessCapabilities` property shows AP support; 1.50 added AP channel width config; 1.58 band accepts 6 GHz (AP on 6 GHz needs regulatory/driver support) [V]. Single-radio concurrency (STA+AP) depends on driver; NM will drop the station link on most chips.

**WireGuard.** Native: connection.type=wireguard, `wireguard` setting (private-key with secret flags, listen-port, fwmark, mtu, peers array: public-key, endpoint, allowed-ips, preshared-key, persistent-keepalive) [K]. D-Bus can create all of it. No `.conf` import over D-Bus: parsing wg-quick files is client-side (nmcli/libnm `nm_conn_wireguard_import` exists in nmcli, not as a D-Bus method) [K]. Nexus would parse wg-quick itself and call AddConnection2. 1.54 added IPv6 endpoint rpfilter handling; 1.56 nmcli peer management [V]. Notably WireGuard private key may be agent-owned; secrets then come via the agent.

**VPN import.** Not available over D-Bus. Import/export is a libnm API (`nm_vpn_editor_plugin_import`, loaded from `libnm-vpn-plugin-*.so` editor plugins, used by nmcli `connection import type openvpn file x.ovpn`) [K]. D-Bus only has VPN setting (`vpn.service-type`, `vpn.data`, `vpn.secrets`) and `VPN.Connection` signals. So Nexus either (a) shells out to `nmcli connection import` (needs the plugin editor libs installed, e.g. networkmanager-openvpn), (b) links libnm via FFI (heavy), or (c) writes its own .ovpn -> `vpn.data` mapper for the common options (remote, ca, cert, key, auth-user-pass, tls-auth, cipher). Recommendation: (a) with fallback message, v1 scope. 

**802.1X.** `802-1x` setting: eap list (peap, ttls, tls, fast, leap, pwd), identity, anonymous-identity, phase2-auth/autheap, password (+password-flags), ca-cert / client-cert / private-key (blob or `file://` path scheme), `ca-path`, `domain-suffix-match`, `altsubject-matches`, `system-ca-certs` (uses system store, 1.2+ recommended for eduroam), `phase1-peapver`. Certs inline as byte arrays with `file://` or `data:` forms; password prompting goes through SecretAgent with hints [K]. Pitfall: no CA = NM warns; eduroam wants domain-suffix-match.

**MAC randomization.** `802-11-wireless.cloned-mac-address` (`permanent`, `preserve`, `random`, `stable`, `stable-ssid`, explicit) and `assigned-mac-address`; `wifi.scan-rand-mac-address` global in NetworkManager.conf (default yes) for scan. Ethernet has `802-3-ethernet.cloned-mac-address`. Changes apply on next activation [K].

**Mobile broadband.** NM delegates to ModemManager; NM exposes `Device.Modem` (+ `gsm`/`cdma` settings: apn, pin, number, password, auto-config), SIM PIN via SecretAgent (`gsm.pin`). Modem details (signal, operator, SMS) live on ModemManager's own D-Bus API; needs `ModemManager.service` running, else StateReason MODEM_MANAGER_UNAVAILABLE 52 [V enum]. 

**Bluetooth PAN/DUN.** NM `bluetooth` setting (bdaddr, type=panu|dun); requires `NetworkManager-bluetooth` plugin and BlueZ; device pairing/trust is BlueZ's API (`org.bluez`), not NM. NM lists `Device.Bluetooth` only for paired devices with NAP/DUN profiles. DUN also needs ModemManager [K].

**Proxy / DNS / metered.** `proxy` setting (method none/auto, pac-url, pac-script, browser-only) — NM only stores and exposes via `Config.Proxy`; apps/pacrunner apply it, Wayland desktop apps mostly ignore it. DNS: `ipv4/ipv6.dns`, `dns-search`, `dns-priority`, `dns-options`, `dns-over-tls`, `llmnr`, `mdns`; `NetworkManager.conf [main] dns=` (systemd-resolved, dnsmasq, default). `connection.metered` yes/no/unknown(guess) and property `Metered` (NMMetered) on Manager/Device; 1.56/1.58 no changes found in NEWS read [V partial]. `connection.zone`, `connection.metered` apply live unless no-reapply flag [V].

**Polkit.** `Manager.GetPermissions()` returns dict action->"yes"/"no"/"auth" and `CheckPermissions` signal on change [K]. Key actions: `network-control` (enable/disable networking, sleep), `wifi.share.protected/open` (hotspot), `wifi.scan` (RequestScan), `settings.modify.own` (user-owned profiles), `settings.modify.system`, `settings.modify.hostname`, `settings.modify.global-dns`, `enable-disable-wifi/wwan/wimax`, `checkpoint-rollback`, `reload`, `sleep-wake`. On a stock logind active local session, polkit's NM rules grant these to the active session without auth (shipped default pkla/rules for `network-control`, `wifi.scan`, `settings.modify.own`; `settings.modify.system` is `auth_admin_keep` unless the distro or user adds a rule, and Arch's package ships only the `org.freedesktop.NetworkManager.rules`? — [unverified], typical Arch behaviour: users in `wheel`/`network` group via polkit rule if configured). A user systemd daemon is in the user's logind session scope (`systemd --user` under session or lingering): lingering without an active session may be "inactive" and get `auth`. Nexus must query GetPermissions at startup and on CheckPermissions and grey out actions (not assume).

**Version notes (1.58.1 on Arch) [V from NEWS]:** 1.58: managed state persistable across reboots via D-Bus; WPA3-SAE mismatch now re-prompts instead of failing; WPA-PSK honours auth-retry and only prompts on final attempt; 6 GHz band setting; iwd-backend power save; connectivity changes above. 1.50: connectivity timeout, AP channel width. Remaining 24k chars of NEWS and pre-1.50 history unread.

## 2. Pitfalls (full list)

1. **Multiple Wi-Fi devices**: keep per-device model keyed by object path; AccessPoints are per-device; same SSID visible on both; profiles can be pinned via `connection.interface-name`; AddAndActivate needs explicit device.
2. **Hidden SSIDs**: `802-11-wireless.hidden=true` required; the APs list never shows them; probe scan with `RequestScan({ssids:[ay]})` [K]. SSID is bytes, not UTF-8 (render lossy, key by bytes).
3. **WPA3/SAE and transition mode**: AP `WpaFlags/RsnFlags` tell key-mgmt (`KEY_MGMT_SAE` 0x400, `KEY_MGMT_PSK`, OWE, 802.1X); in transition mode both bits appear. Create profile with `key-mgmt=sae` only if AP lacks PSK (else `wpa-psk`); PMF settings (`pmf`) matter; wrong password under SAE historically came back as generic timeout, 1.58 now re-prompts [V]. Older/Broadcom/some drivers fail SAE.
4. **6 GHz**: needs regulatory domain, band `a` vs 6 GHz in 1.58 [V]; only WPA3/OWE allowed; APs visible only if driver supports; frequency 5955+ MHz distinguishes band.
5. **Signal flapping/roaming**: `AccessPoint.Strength` changes constantly; same SSID has many BSSIDs and `ActiveAccessPoint` changes on roam; aggregate per SSID (max strength), debounce/hysteresis, do not re-sort the list under the cursor.
6. **Scan throttling**: `RequestScan` is rate-limited by NM (refused if last scan < ~10 s; `org.freedesktop.NetworkManager.Device.NotAllowed`/ "Scanning not allowed immediately following previous scan") and polkit `wifi.scan`; also when device is connecting; use `LastScan` (CLOCK_BOOTTIME ms; -1 never) to decide, and don't spin [K]. NM autoscans in background anyways.
7. **Duplicate SSIDs / profiles with same name**: `connection.id` is not unique; use UUID/path; multiple profiles per SSID exist (nmcli creates "SSID 1"); match AP to profile via `Connection.Settings.FilterConnections`/ `Device.AvailableConnections` and `Wireless` security compatibility.
8. **NM restarting**: name owner changes (`NameOwnerChanged`): drop all cached proxies, re-register SecretAgent (registration is lost), resubscribe, full resync; show "NetworkManager unavailable" state, not crash. Also re-register after NM crash with in-flight GetSecrets cancelled.
9. **Signal storms**: `PropertiesChanged` on APs while scanning (dozens of APs x Strength), `ObjectManager`-style InterfacesAdded bursts at startup/resume; coalesce to a ~100-250ms frame tick; subscribe only to needed paths (AP signals only while Wi-Fi view is open).
10. **Sleep/resume**: NM `Sleep(true/false)`, state ASLEEP(10); devices go through reasons 37/73; Wi-Fi APs list stale after resume (clear on resume, re-scan); logind `PrepareForSleep` signal to pre-pause UI; connections reactivate with new IP.
11. **rfkill / airplane mode**: `WirelessEnabled` (settable, polkit), `WirelessHardwareEnabled` (read-only hard switch); `WwanEnabled`; Bluetooth rfkill is outside NM; `NetworkingEnabled`. Hard-blocked ≠ soft-blocked: disable the toggle and explain.
12. **Wrong password detection**: no single reason. Typical: device goes ACTIVATING(CONFIG) -> NEED_AUTH(60) -> back to CONFIG ... -> FAILED with SUPPLICANT_DISCONNECT(8)/NO_SECRETS(7)/SUPPLICANT_TIMEOUT(11); with a SecretAgent present NM calls GetSecrets with REQUEST_NEW after a bad 4-way handshake [V flag meaning]. Best signal: second GetSecrets call with REQUEST_NEW within one activation = "password rejected". If no agent registered, NM fails with NO_SECRETS. 1.58 changed prompt timing (only at final auth-retry for PSK) [V].
13. **DHCP timeouts**: reasons 15-17 / IP_CONFIG_UNAVAILABLE 5; ipv4 `dhcp-timeout` default 45 s; show "connected, waiting for IP" progress from IP_CONFIG state (70), allow `may-fail` for dual stack.
14. **IPv6-only / dual stack**: `ipv4.may-fail=true` default; connectivity check may report LIMITED if probe URI IPv4-only; show IPv6 address when ipv4 empty; DNS64/NAT64/CLAT; `ipv6.method=auto` RA timeouts; per-family `Ip4Connectivity`/`Ip6Connectivity`.
15. Others: rebuilt `AccessPoints` ordering; `Settings.NewConnection/ConnectionRemoved` for profile list; `Unsaved` profiles; external changes by nmcli (use version-id); `ConnectionAssumed` after NM restart; agent-owned secrets plus keyring unavailable in headless session.

## 3. iwd + networkd + resolved

**iwd D-Bus (`net.connman.iwd`)** [K]: objects Adapter, Device (Powered, Scan, GetOrderedNetworks, Disconnect, Mode station/ap/ad-hoc), Station (Scan, ConnectHiddenNetwork, State, ConnectedNetwork, Scanning, signal-level agent via `RegisterSignalLevelAgent`), Network (Connect, KnownNetwork, Type), KnownNetwork (Forget, AutoConnect, Hidden), AccessPoint (Start/StartProfile for hotspot), AgentManager (`RegisterAgent`: iwd calls RequestPassphrase / RequestUserPassword etc. on the client — the equivalent of NM's SecretAgent), SimpleConfiguration (WPS), Diagnostic, DeviceProvisioning (DPP), AdHoc. Access is gated by D-Bus policy file `/usr/share/dbus-1/system.d/iwd-dbus.conf`: default allows root and group `netdev`? (iwd ships policy: root owns; `at_console`/ group `wheel`/`netdev` `send_destination` allowed — [unverified] exact groups; the iwd.conf policy allows `at_console="true"` users). So an unprivileged session user can scan, connect, forget, start AP without root. Not provided over D-Bus: iwd config (`/etc/iwd/main.conf`), saved network files live in `/var/lib/iwd/*.psk|.8021x|.open` root-owned (KnownNetwork only lets you forget/toggle autoconnect/hidden); enterprise profiles must be written as files (privileged) or supplied via agent only partially; MAC randomization & static IP settings are in main.conf/network files.

**systemd-networkd/resolved** [K]: networkd configuration = files in `/etc/systemd/network` (root); its D-Bus is limited: `org.freedesktop.network1.Manager` (ListLinks, GetLinkByName/Index, Describe, Reload, ReconfigureLink, ForceRenewLink, RenewLink, `Link` objects with SetDNS/..., Revert, Describe) — runtime-only changes via polkit actions `org.freedesktop.network1.*` (reload, reconfigure, renew, forcerenew, set-ntp-servers, set-dns-servers, set-domains, set-llmnr, set-mdns, set-dns-over-tls, set-dnssec, set-dnssec-negative-trust-anchors, revert-ntp, revert-dns, ...). Static address/route/DHCP-mode/VLAN/bridge/wireguard (netdev files) changes need writing files then `Reload`, which needs root or a privileged helper (polkit auth_admin by default). networkd also does not do WireGuard key mgmt over D-Bus; keys live in .netdev files (mode 0640 root:systemd-network). resolved: `org.freedesktop.resolve1` — Manager `SetLinkDNS`, `SetLinkDomains`, `SetLinkDNSOverTLS`, `SetLinkLLMNR`, `FlushCaches`, `ResetServerFeatures`, `ResolveHostname`, statistics; polkit `org.freedesktop.resolve1.set-dns-servers` etc. (default for active local session: `auth_admin_keep`? [unverified]). No captive-portal detection, no metered concept, no VPN plugin, no secret storage, no 802.1X (iwd does), no mobile broadband/BT PAN (separate ModemManager/bluez).

**Privileged helper cost:** for persistence (profiles, static IP, WireGuard) you need a root-owned helper (setuid binary is wrong; use polkit-gated D-Bus system service or socket-activated systemd service) that writes validated files into `/etc/systemd/network`, `/var/lib/iwd`, calls `networkctl reload`. That adds a root attack surface (path traversal, file content injection e.g. `[Match]` rules hijacking links, secret handling for WireGuard keys / PSKs), a polkit policy to ship and maintain, packaging complexity, and the requirement that the helper be auditable and minimal. Without it, the unprivileged daemon can only do iwd Wi-Fi + runtime resolved DNS tweaks.

**Dual backend worth it?** Not for v2.0. Reasons: capability gap is large (no connectivity/portal, VPN, profiles, metered, mobile, BT in iwd+networkd stack), doubling the model/error-mapping/test surface, and the iwd stack needs a privileged helper which contradicts the "unprivileged user daemon" principle. Cheap hedge: define a thin `Backend` trait with capability flags (what the UI can show), implement NM only; optionally add an iwd-only "Wi-Fi only" backend later (iwd D-Bus is accessible unprivileged and the model is small) — NM itself can also use iwd as its Wi-Fi backend (`wifi.backend=iwd`, power-save supported in 1.58 [V]), so iwd users who like NM are covered through the NM backend.

## Verdict
NM over D-Bus (zbus) as sole v2.0 backend; backend-trait with capability flags; iwd-direct as a possible later read/connect Wi-Fi module; skip networkd. Confidence: medium-high on API shape, medium on polkit defaults and iwd policy groups (flagged unverified).
